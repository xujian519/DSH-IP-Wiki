# dsh-ip-wiki

DeepSeek Harness 的 **IP 知识库面板**插件：把本地卡片库搬到 Harness 里看——卡片树、卡片阅读、整理报告，一个屏幕看完，不再为了看一眼卡片去开 Obsidian 或文件管理器。

目标用户：专利代理人、专利律师、知识产权从业者（首期自用）。

## 它做什么

侧边栏出现「IP 知识库」入口，点开是主面板：

| 区域 | 内容 |
|---|---|
| 顶部状态条 | 库根路径、卡片总数与分型计数、索引生成时间与**索引漂移**（索引与磁盘卡片是否一致）、报告数、待确认数 |
| 左栏检索框 | **提问式检索**：用一句话问（"修改超出原范围怎么判断"），结果带片段与出处；每条的排序级别（关键词 / 语义 / 语义+精排）与分数都写明，降级原因（如未读到本地 key）直接显示 |
| 左栏卡片树 | 按卡型（概念卡 / 规则卡 / 案例卡 / 法条卡）→ 业务域分组，点开即读；顶部另有「待确认清单」（低置信卡片） |
| 左栏报告 | `reports/` 下的整理报告（映射、去重、lint），表格按原样渲染 |
| 右栏阅读器 | 卡片正文（Markdown；标题 / 列表 / 引用 / 代码 / 表格 / `[[双链]]` 均可读）、卡型 / 域 / 概念 / 状态 / 置信度 / 质量 / 辖区 / 法条依据 / 来源路径 |

## 面板界面

界面只消费主题令牌（`--dsw-*`），不引图标库、不写死颜色，亮暗两套配色共用一份样式：

- **中性面从墨水派生**：亮色下 `bg-base` / `bg-layer-1` / `bg-layer-2` 三个令牌同为白色，所以悬停底、表头、按钮底一律用 `--dsw-alias-interactive-bg-hover` 或 `color-mix(… label-primary N%)`；树栏与标题行用 `--dsw-specific-sidebar-fill`，两栏因此在亮色下也有分界。
- **色相只留给状态**：卡片状态、门禁档位、差异行用「色点 / 描边 / 行底」表达色相，文字回到主色——亮色下 warn 2.15:1、success 2.28:1，当文字色不合格。
- **正文有版心**：散文块 40 字宽（表格与代码块满宽横滚），标题三档，正文字号跟随客户端的内容字号偏好。
- **树行单行 30px**：1,137 张的列表是拿来扫的——标题截断并挂 `title`，行高恒定。
- **互链可达**：正文 `[[页面名]]` 与「相关卡片」（按 id）都能点开；解析不到的保持纯文本，不做"看着能点却没反应"的样子。
- **树先给你地图**：域分组默认收起，`Shift+X` 全展/全收，树内有按标题的即时筛选（纯前端、不发请求）；命中时用扁平列表替换分组视图。
- **卡片头只讲一次**：卡型与状态只出现一次，置信度/辖区/法条/来源/id/path 收进可折叠的「元信息」；正文首个与标题相同的 `#` 不再重复渲染，目录里每一项都能真的跳。
- **删除是唯一不可撤销的动作**：卡片页右上角「删除」是 danger 变体，二次确认行写明"此操作不可回滚"；确认后**先清掉其它卡里指向它的关联、再删文件**，最后重建索引，横幅报「已删除 X / N 处关联已清掉」。它没有对应的智能体工具——永久删除只在面板里发生。
- **危险操作分档**：读与导航是 `.iw-btn-quiet`（无底、次级墨），落库是 `.iw-btn-primary`，「作废」「回滚」「删除」是 `.iw-btn-danger`——它们不该和「刷新」长得一样。
- **批量确认先问后写**：`全部确认（N）` 先展开确认行，执行中状态条报 `正在落库 N/总数`；近千次写库不该藏在一句「正在读取…」后面。
- **失败可重试**：错误横幅自带「重试」，重跑树 / 草稿 / 门禁三个读取。

取舍、负控制与未做的部分见 [面板视觉与安全一轮](docs/notes/implemented/2026-09-29-panel-visual-and-safety-pass.md)。

## 检索

三级管线、逐级降级：**关键词 BM25**（内存现建）→ **本地嵌入** `bge-m3-mlx-fp16` → **本地精排** `BAAI-bge-reranker-v2-m3-mlx-fp16`。任一级不可用或报错就退回上一级，并在结果里写明原因；请求不会失败。

**嵌入一次，之后都从缓存来**：整库按 32 张一批嵌入，向量缓存在**库外**（`embedding.apiKeyFile` 同目录，默认 `~/.dsh/ip-wiki/vectors.json`，float32，真库 6.4 MB），插件装载时后台预热，不阻塞检索。真库实测：冷启动那一轮的 20 题验收跑 **498.5 秒**，有缓存之后同一轮 **79.7 秒**；20 题在部署的 20 秒超时下全部走到精排级（修复前每一题都会退回关键词）。面板「检索」档位旁会显示「预热 N/M」，全部就绪时不显示。

智能体工具（同一套实现，模型与面板不会给出不同答案）：

| 工具 | 用途 |
|---|---|
| `ip_wiki_search` | 检索卡片库：命中卡片 + 片段 + 出处（法条 / 来源路径）+ 实际检索级别 |
| `ip_wiki_get` | 按路径读一张卡的完整正文 |
| `ip_wiki_cite` | **逐字核对**一处引用是否真在卡里，命中给上下文，不命中报"没有这段原文" |

实测验收（20 题真实业务问题、真端点 + 真库 139 张：117 在用 / 22 已废弃）：**命中@1 = 17/20，命中@3 = 19/20**，全部由精排级排序。金标以**合并卡**为正解（20 题里有 4 题原本指向的卡已被合并取代；同一轮沿用旧金标实测为 14/20、16/20——两个数并列记录，不当成“修好了涨 3 分”的证据）。复跑：`DSH_IP_WIKI_EVAL=1 pnpm exec vitest run tests/p1-eval.spec.ts`。

**导入 Wiki 批次后**（真库 1,137 张：117 已确认 / 998 未确认 / 22 已废弃）同一套 20 题的实测是 **命中@1 = 13/20，命中@3 = 16/20**，声明线（14/18）仍红着：多出来的 998 张里有大量同主题材料，精排给它们的分数确实更高，而验收的金标全在整理层。逐题的走线证据、被否掉的几种修法（同主题限席 / 排名融合 / 整理层整层优先）见设计文档 §23–§24 与决策记录 `docs/notes/implemented/2026-09-29-pool-size-and-near-duplicates.md`——**声明线与金标都没动**。

每个阶段给下一级 **40 个候选**，其中每个召回阶段保底 20 席（`STAGE_SLOTS`）。库到 1,137 张后，关键词侧一次给出一千多个候选、归一化分又都贴近 1，20 席的池子会被它占满，向量级排第 5 的卡就进不了精排——实测有一题的金标因此在关键词级第 20、向量级第 19 处被挡在池外；池子放到 40 后它进池并被精排排到第 2。

**已废弃卡不抢答**：被合并取代的卡仍会被返回（可能有人记得旧措辞），但排在**所有在用卡之后**，只有命中不足时才露头；结果头写明本次扫描里有多少张已废弃（工具写「已废弃 N 张排在末尾」，面板写「已废弃 N」）。翻旧措辞的入口是合并卡正文末尾的「合并说明」表和面板卡片树。

**近似重复的卡也只占一个位置**：与列表里更靠前的某张卡余弦 ≥ 0.97 的候选（同一问题被改写出来的多张卡最典型；实测同题改写 0.97–1.00，而同一页的不同章节碎片只有 0.87–0.96）会被排到末尾，仍在结果里、只是不再连续占位；数量写进结果头（工具写「与前一张重复 N 张排在末尾」，面板写「近似重复 N」）。在用卡与已废弃卡各自做一遍再拼接，所以它不会把在用卡排到已废弃卡后面。判定用的是嵌入向量，语义阶段不可用时这条规则不生效（两者都降级为纯分数排序）。

## 质量门禁（整理质量可量化）

确定性规则跑一遍，分三档给结论；面板「质量门禁」、工具 `ip_wiki_lint`、路由 `GET /dsh-ip-wiki/lint?failOn=` 同一套实现：

| 规则 | 档位 | 判据 |
|---|---|---|
| `missing-title` / `empty-body` | critical | 卡片不可用 |
| `broken-link` | warning | `related_concepts` 指向库里不存在的卡片（按卡片 id 或迁移前的 `from_id` 解析） |
| `duplicate-title` | warning | 标题归一后重复（抓逐字/近同题，给去重提供锚点）；只比较**在用**卡，被合并取代的卡不算重复 |
| `index-drift` / `index-missing` | warning | 派生索引与磁盘不一致 / 不可读 |
| `unclassified` / `missing-concept` / `low-confidence` | suggestion | 未归类、无概念标签、置信度 < 0.8 |
| `orphan-card` | suggestion | 既没有关联、也没被关联 |
| `wanted-card` | suggestion | `wiki_links` 里被 10 张以上卡提到、却仍没有对应卡的目标（按被提到次数降序，就是「下一步该建哪些卡」的清单） |
| `island-domain` | suggestion | 某个业务域（≥5 张在用卡）与其它域**双向零互链**——一个外部进不去的孤岛 |

`failOn`（默认 `warning`）决定哪一档算失败；结论是 `pass` / `fail`。

**试点期实测（30 张卡）**：0 critical；77 条 finding —— 断链 57、未分类 10、低置信 6、标题重复 4。其中标题重复 4 条正是迁移已记录的**两对逐字同题**（2 对 × 2 张），门禁独立复现了它；断链 57 条来自 30 张试点卡的交叉引用大量指向**尚未迁移的 100 张卡**——这条数字本身就是"该做全量迁移"的证据。

**全量库实测（139 张）**：0 critical、0 warning，61 条 suggestion（未分类 31、低置信 29、孤立卡 1），`failOn=warning` 判 **pass**。复跑：`DSH_IP_WIKI_EVAL=1 pnpm exec vitest run tests/p3-eval.spec.ts`。

## 去重与合并（保留原文、可回滚）

```
ip_wiki_lint（读 duplicate-title 命中）→ ip_wiki_draft(supersedes=[重复卡…])
   → 面板看合并卡差异 + 「将弃用」清单（可点开被弃用的卡对照）
   → 确认：写入合并卡，并把被弃用的卡改成 status: "deprecated" + superseded_by: "<合并卡路径>"
   → 回滚：合并卡删除/还原，被弃用的卡按字节恢复
```

被弃用的卡**原文一字不改**（只在 frontmatter 上加两行），并且不再计入“重复标题 / 孤立卡”规则——否则合并解决了问题，门禁却永远红着。它们也不再抢答：检索把已废弃卡排在所有在用卡之后。

**真库实测**：全量库 9 组 22 张逐字同题一次合完（先在真库副本预演，2026-09-29 在面板确认落库）：重复标题 finding **22 → 0**，22 张转 `deprecated`（正文逐字节未变，只改 `status` 一行 + 加 `superseded_by` 一行），索引 139/139 无漂移，`broken-link` 仍为 0；9 份整批回滚后**树哈希逐字节复原**。落库后真库 139 张：117 在用 / 22 已废弃。

### 批量合并现成的重复组

`scripts/merge-duplicates.ts` 把库里一组组重复卡各收成一张合并卡（**只生成草稿**，从不写卡片）：

```sh
tsx scripts/merge-duplicates.ts --root <库根> --dry                        # 只打印方案
tsx scripts/merge-duplicates.ts --root <库根>                              # 逐字同题的组
tsx scripts/merge-duplicates.ts --root <库根> --groups <分组表.json> --dry  # 相似度量出来的组
```

不指定 `--groups` 时，组来自"标题归一后相同"（就是门禁 `duplicate-title` 报的那些）。**那条规则只是候选生成器**：它把"的"抹掉，于是 `方法专利延伸保护` 与 `方法专利的延伸保护`、`权利要求解释` 与 `权利要求的解释` 也算同题——真库里这 4 组实测**都不是重复**（组内余弦 < 0.95、覆盖率 < 0.5、J < 0.15），按标题合并会弃用内容不同的真卡。跨标题的重复要由相似度仪表给组：库侧 `tools/near_duplicates.py` 算三个信号（嵌入余弦 / 正文 5-gram 精确 J / **覆盖率**），合并判据是**覆盖率 ≥ 0.90 且 J ≥ 0.30**（被吸收的那张至少九成内容在留存卡里），输出 `reports/near-duplicates.md|json`，再由它导出 `{"groups":[{"title","paths"}]}`。`--groups` 只换组的来源，组装、备份、回滚、`supersedes` 语义一字不动。

合并卡是**组装**出来的，不是重写的：正文取该组 `quality` 最高的一版（并列时取已归入业务域的那一版），frontmatter 沿用该版并追加 `supersedes`（全部成员 id，含正文来源那张）、`merged_from`（成员路径）、`merged_at`、`merge_note`，正文末尾追加一张「合并说明」表列出每个成员的质量分与处置。组内**每一张**（含正文来源那张）都被弃用——否则重复标题还在。没有文本被删掉：被弃用的卡原文留在库内。

**真库实测（2026-09-29，覆盖率判据）**：1,137 张量出 20 组 41 张冗余卡（覆盖率 0.90–1.00；9 组是"主内容 + 它的拆分片段"、8 组是 vault 两棵树各存一份同文、3 组是同目录同文两页），已写成 20 份合并草稿等面板确认。已落库的 9 组是这台仪表的正控制（9/9 召回）。

### 批量导入 vault 的 Wiki 页

`scripts/import-wiki.ts` 把 vault 编译好的 `Wiki/` 页收成卡片（**只生成草稿**，从不写卡片）：

```sh
tsx scripts/import-wiki.ts --root <库根> --dry --report <报告路径>   # 方案 + 全量报告
tsx scripts/import-wiki.ts --root <库根> --batch 1                   # 写这批草稿，等你在面板确认
```

判定与映射（决策记录：`docs/notes/implemented/2026-09-29-wiki-import-mapping.md`）：

- **按内容量测，不按文件名**：导航/元数据页（`index.md`、`All-Concepts*` 等）不收；正文 < 200 字的壳页（拆分家族的索引壳、书籍骨架、只有 frontmatter 的 stub）不收。正文量计入普通段落、长引用块（条文原文在引用块里）、长标题行（个人笔记把整段写在 `###` 行），并先剥掉 frontmatter。
- **正文逐字节相同的页只留一张**（按 sha256 去重并报告）。
- **标题三级回落**：`# ` 标题 → 通用小节名（决定要点/裁判规则/核心要点…）或**被多页共用**（系列名）时回落文件名 → 去掉尾部 `（N）` 复制标记。
- **正文原样搬运**（组装，不重写），因此 `ip_wiki_cite` 能逐字核对；`concept` 取 vault 自己的 `wiki-concept-index.json`；`law_refs` 从页内 `《…》第…条` 抽取；`source.kind = "vault-wiki"` 记原始路径。
- **`related_concepts` 由页内 `[[…]]` 解析而来，且在整批内解析**：所以整批**一次落库**，`broken-link` 保持 0；解析不出的目标记在 `wiki_links`，不进门禁。
- **幂等**：时间戳取源文件 mtime，草稿 id 由"目标路径 + 卡片全文"决定，同一份 vault 重跑不重复排队。
- **落库即 `status: "draft"`**：落库 ≠ 有人读过；之后用 `ip_wiki_confirm` 排队确认。

## 索引重建（门禁报的漂移，面板里一键修）

派生索引 `index/card-index.json` 只由卡片决定，所以：

- **写卡片时自动跟上**：每次确认 / 回滚后重建索引，且**重建前把旧索引字节并入这次草稿的备份**（`.dsh-ip-wiki/backups/<草稿 id>/index/card-index.json`）。
- **回滚就是把旧字节放回去**（不是"再重建一次"）——所以 confirm→revert 之后库**逐字节复原**，真库哈希实测如此。重建只覆盖 9 个字段（`schema_version / library / generated_at / total_cards / by_type / by_domain / cards[]`），迁移写的 `source_index_last_updated` 等字段**原样保留**，卡片条目字段与迁移完全一致。
- **外部改过卡片**（脚本 / 手工）：门禁会报 `index-drift`，面板「质量门禁」里有「重建索引」按钮，工具/路由是 `POST /dsh-ip-wiki/index/rebuild`。

## 素材 → 卡片（草稿 + 差异预览 + 确认）

```
素材（PDF / 图片 OCR / 网页 / 会话）→ 归纳成卡片文本 → 草稿区 .dsh-ip-wiki/drafts/
   → 面板里看差异（+/- 逐行） → 你点「确认落库」 → 写进 cards/ → 出现在检索结果里
                              → 你点「作废」   → 只进 archive/，cards/ 不变
   → 落库后想撤：「回滚」把被替换的卡片按字节恢复，或删掉这次新建的卡片
```

| 谁做 | 做什么 |
|---|---|
| 智能体（`ip_wiki_draft` / `ip_wiki_confirm` / `ip_wiki_review`） | 把素材归纳成卡片文本、提交草稿；提交状态确认草稿；`review` 支持 list / view / confirm / discard / revert |
| 你（面板） | 看差异、点确认或作废；落库后可一键回滚（单份或整批） |
| 插件不做的 | 不自己抓网页、不做 OCR、不做摘要 —— 抽取由本机工具与模型完成，插件只管**草稿、差异、门禁、审计、回滚** |

**未确认的草稿对模型不可见**：读取与检索只扫 `cards/`，草稿在 `.dsh-ip-wiki/` 里，这是结构性的（有测试钉住）。

**来源分级**（`sourcePolicy`，默认 `clientMaterial: local-only`）：客户材料默认只允许本地模型。声明 `generatedBy: "dsh-model"` 的客户材料草稿会被**拒绝**——插件拦不住模型已经看过素材，但能拒绝把"云端生成"写进库。

**审计**：`.dsh-ip-wiki/log.md` 只追加（时间 / 动作 / 草稿 id / 目标 / 来源与策略 / 结果）。

**写入面**：`cards/` 只被 `confirm` 写，且先备份到 `.dsh-ip-wiki/backups/<草稿 id>/`。库内不留插件的其他产物——检索的关键词索引只在进程内存里，向量缓存则落在**库外**（`embedding.apiKeyFile` 同目录下的 `vectors.json`，默认 `~/.dsh/ip-wiki/`），所以库本身在任何机器上都能原样搬走。

## 确认入库（把已入库的「未确认」卡变成「已确认」）

迁移与批量整理写进来的卡片，frontmatter 是 `status: draft`——意思是**还没有人确认过它**。确认也是一次写库，所以走同一条路：

```
ip_wiki_confirm（工具：paths 指名，或 scope="all-draft" 全库）
   → 为每张卡生成一份「状态确认」草稿（.dsh-ip-wiki/drafts/）
   → 面板「待确认草稿」逐份看差异 → 点「确认落库」（单份）或「全部确认（N）」（整批：先展开确认行，点「继续」才开写，执行中状态条报「正在落库 N/总数」）
   → 卡片变为 status: confirmed，检索结果与卡片头显示「已确认」
   → 想撤：草稿页的「回滚」，或落库后横幅里的「回滚」（整批按相反顺序逐份还原）
```

- **确认只改一行**：草稿与卡片的差异只有 `status` 一行，其余逐字相同（有测试钉住）。
- **从磁盘现算，不吃旧文本**：确认时按卡片**当时**的内容只翻 `status`，所以草稿排队期间正文被改过，也不会被草稿里的旧正文覆盖；卡片已被删则**响亮拒绝**。
- **不是质量结论**：确认只回答"这张卡我看过了、允许它进正式库"，门禁 finding 计数不受影响（真库实测确认前后一致）。
- **未确认 ≠ 不可检索**：检索照常返回未确认卡，并在结果里标出「状态：未确认」，由使用者决定是否引用。
- **已废弃 ≠ 被隐藏**：检索仍会返回被合并取代的卡，但排在所有在用卡之后（见「检索」）。
- **批量可回滚**：真库副本实测 139 张里 117 张放回 `status: draft` 再 117 份提交 → 117 份确认 → 117 份回滚，**树哈希逐字节复原**（索引字节也一并放回）。130 张的迁移后状态（2026-09-29）走的就是这条路。

## 配置

库根是**必填**配置项，写在 bundle 的 `cordis.patch.yml` 行里：

```yaml
- insert:
    - id: dsh-ip-wiki
      name: 'dsh-ip-wiki'
      config:
        libraryRoot: /Users/xujian/projects/LLM-wiki-card
        embedding:
          enabled: true
          baseUrl: http://127.0.0.1:8000
          embedModel: bge-m3-mlx-fp16
          rerankModel: BAAI-bge-reranker-v2-m3-mlx-fp16
          apiKeyFile: /Users/xujian/.dsh/ip-wiki/config.json
          timeoutMs: 20000
          rerank: true
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `libraryRoot` | 无（必填） | 卡片库绝对路径；缺/空/相对路径 → 加载时**响亮失败**（不会静默指向错的目录） |
| `embedding.enabled` | `true`（有配置块时） | 关闭则只用关键词 |
| `embedding.baseUrl` | `http://127.0.0.1:8000` | OpenAI 兼容端点 |
| `embedding.embedModel` / `rerankModel` | `bge-m3-mlx-fp16` / `BAAI-bge-reranker-v2-m3-mlx-fp16` | **必须是端点里的全名**（短名会 `not_found_error`） |
| `embedding.apiKeyFile` | `~/.dsh/ip-wiki/config.json` | 内容 `{"apiKey":"…"}`，**库外**；读不到只降级、不报错 |
| `minScore` | `0.25` | 语义候选的相关度下限 |

## 库约定

```
<库根>/
├── cards/{concept,rule,case,statute}/*.md   # 卡片：YAML frontmatter + Markdown 正文
├── index/card-index.json                    # 派生索引（面板只用来对照，不当作真源）
├── reports/*.md                             # 整理报告
└── raw/                                     # 原始素材留档（插件不读不写）
```

- **真源是 `cards/` 下的文件**：面板直接扫盘，索引只作交叉核对，因此索引过期会显示成「索引计数与卡片不符」而不是显示错数据。
- **卡片类型**：`type` 为 `concept` / `rule` / `case` / `statute` 之一；缺 `type` 或类型未知的文件被当作非卡片跳过。
- **缺省值**：无 `domain_l1`/`domain_l2` → `未分类`；无 `status` → `draft`；无 `title` → 取正文第一个一级标题。
- **待确认清单**：`confidence < 0.8` 的卡片，按置信度升序（同分按标题）。

## 边界与限制（诚实列出）

1. **写入只有两条路**：草稿只落 `.dsh-ip-wiki/`；`cards/` 只在确认时被写，且可回滚。卡片互链的落库仍待做。
2. **改代码要重启**。宿主半边是启动时载入模块的：换了 `lib/` 需要重启 Harness（或重载 profile）才生效；客户端半边刷新页面即可。
3. **`[[双链]]` 能跳，但只在解析得出时**。正文里的双链在「卡片 id / 标题 / 文件名 / 页名」里找目标，找到就是可点的控件，找不到保持纯文本——不装作能点。`[[页名#小节|显示文字]]` 这种 Obsidian 写法按页名解析、按显示文字呈现；**锚点只用来认出是哪一页，不做滚动**（跳到卡，不滚到小节）。真库 5,513 条正文双链里按这个口径有 4,125 条可跳，其余的多半正是 `wiki_links` 记下的那批「该建卡」。
4. **无浏览器的真机验证**。渲染逻辑由 jsdom 测试覆盖，未在真实浏览器里跑过交互；面板席位、路由、数据均由实测证据确认（见下）。
5. **库根不可写时不影响面板**：根不存在时状态条给出明确原因，而不是空白。
6. **预热进度是快照**：面板打开时读一次 `/search-status`，不轮询，靠「刷新」更新。向量缓存被同一台机器上的多个库共用——键里含库内相对路径与内容哈希，不会串味，但两个库交替使用会让缓存来回重写。

完整台账——已验收批次、未决事项与事故记录——见 [docs/TECH_DEBT.md](docs/TECH_DEBT.md)。
