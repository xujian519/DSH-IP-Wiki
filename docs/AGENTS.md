# 文档规范

这一篇管**文档本身**：哪一篇装什么、怎么写、以及别写什么。文档里的链接与决策记录的格式由 `tests/gates/` 的两道门禁机器校验（见 [development.md](development.md#五道门禁)）。

## 一篇文档一个家

一个事实只在一个文件里写全，别处只链接。写新内容前先找它的家；找错了家就搬过去（搬运时留一行链接即可）。

| 文件 | 装什么 | 不装什么 |
|---|---|---|
| [AGENTS.md](../AGENTS.md) | 常驻军规：每次会话都要在上下文里的规则，每条一两行 | 可以外链的细节、故事、操作步骤 |
| [README.md](../README.md) | 产品说明：它做什么、怎么装、怎么配、库目录约定、边界与限制 | 内部约束与它们的理由 |
| [architecture.md](architecture.md) | 项目构成 + 不可违反的架构约束 | 功能说明（→ README）、理由与备选（→ note） |
| [development.md](development.md) | 门禁与命令、日常流程、构建与重载、验收评测怎么跑 | 约束本身（→ architecture）、证据标准（→ testing） |
| [testing.md](testing.md) | 什么算证据：负控制、覆盖率纪律、测试哲学 | 命令清单（→ development） |
| [TECH_DEBT.md](TECH_DEBT.md) | 已知缺口、已验收批次、未决事项 | 决策理由（→ note） |
| [notes/](notes/README.md) | 一条决策的为什么与被放弃的备选 | 缺口清单（→ TECH_DEBT）、操作手册 |
| 代码注释 / JSDoc | 那个函数**自己的**契约：前置条件、副作用、时序、为什么不能改 | 复述代码、实现过程的流水账、别处已经写过的规则 |

## 写作规则

- **写当前状态**：文档描述"现在是什么样"，不写"曾经 / 将来"。历史归 git、`docs/notes/` 与 [TECH_DEBT.md](TECH_DEBT.md)（只有那里允许"未做 / 待决"的措辞）。
- **一段一行**：一个自然段写成物理上的一行，靠编辑器软换行折行；表格、列表、代码块保持原样。
- **点名具体的东西**：写清是哪个命令、哪个字段、哪条规则、哪个测试；不用隐喻代替名词。
- **不复述会漂移的手抄清单**：卡片数、finding 计数、端点名这类事实要么带复现命令与日期，要么别写；能链接源文件或报告就链接。
- **不写实现态注解**：正文里不出现「已实现！」「下一步是…」，状态归 [TECH_DEBT.md](TECH_DEBT.md) 与决策记录。
- **注释保持本地**：解释那段代码自己的约束就够，不解释远处的行为、不复述代码在做什么。

## slop 清单（写文档或 review 时逐条查）

- **重复事实**：拿一句话的独特片段全库搜一次；出现两次就留一个家，其余改链接。
- **历史串味**：正文里的"以前 / 后来 / 这次改成"——搬去 note 或台账，正文只留当前事实。
- **推理流水账**：实现步骤、测试走查、被否掉的局部方案写进了正文——留下的应是结论与理由，过程归决策记录。
- **段落墙**：一段话塞了好几条规则加括号插叙——拆开，或把细节降到它的家。
- **强调通胀**：满篇加粗、全大写、"非常重要"——强调只留给真正改变行为的那一句。
- **手抄目录**：手写的文件清单、字段表、规则表——要么从源生成，要么给它一道门禁。

## 链接

- 文档之间用**相对 Markdown 链接**（`[标题](路径#锚点)`），不用绝对路径、不写行号。
- 门禁检查两件事：目标文件存在；带 `#锚点` 时，目标文件里存在 slug 相同的标题（重复标题按 GitHub 的 `-1` / `-2` 后缀规则匹配）。
- 代码块与行内代码里的 `[x](y)` 不参与检查——写示例不必担心。
- 指向仓库之外的链接（`http(s)://`、`mailto:`）不检查。

## 还没有的

字数预算（harness 的 `verify-doc-budgets` 那种上限门禁）**没有做**，文档变长目前只靠 review 管；这一条记在 [TECH_DEBT.md](TECH_DEBT.md) 里。
