# 决策记录（note）

这里是「为什么这么做、放弃了什么」的家：代码与测试能说明**是什么**，说不清**为什么**和**打败了谁**。写法由 `tests/gates/notes.spec.ts` 机器校验（`pnpm run verify:docs` 可单独跑）。

## 位置与命名

`docs/notes/{status}/{yyyy-mm-dd}-{topic}.md`

- **status** 是目录，也是文件里的 `Status:` 行，两者必须一致：`proposed`（提案，尚未实现）| `implemented`（已落地的现实）| `rejected`（考虑过并否决）。
- **日期**是这个话题**第一次被提出**的那天，不是归档那天；文件名用 `-` 连接的英文/拼音短题，如 `2026-09-29-delete-audit-line.md`。
- 目录为空的状态不必建目录——需要时再建。

## 什么时候写一条

**非平凡变更**在同一批改动里带一条 note：改行为、改架构、改契约（路由 / 守卫 / 配置字段）、改流程、改格式。以下豁免：

- 机械或局部编辑：改错别字、调一条面板文案、重命名一个内部变量、跟随已有决策的小改动。
- 已经有一条 note 拥有这个决策——**更新那一条**（路径、名字、默认值这类事实跟随代码改），不要另写重复的一条。

**一条 note 不许被改成另一个决策**：新决策另写一条，并在两条里互相链接；旧的那条保留它当时的理由。

## 文件格式

```markdown
# Note: <标题>

Status: implemented

## Problem

<不依赖解决方案也能读懂的问题：现状哪里不对、被什么量出来的>

## Decision

<已落地的现实，现在时；数字与命令要能被重跑>

## Alternatives considered

- **<备选方案>** —— 为什么落选（代价、被否掉的证据）

## Consequences

<换来了什么、付出了什么；仍未做的写清楚>
```

规则：

- 首行必须是 `# Note: ` 开头且标题非空；第三行必须是 `Status: `。
- 四段 `##` 骨架必写且按序：`## Problem` → `## Decision` → `## Alternatives considered` → `## Consequences`。中间可以插入自定义的 `##` 小节（已有的例子：「## 负控制」「## 验收」），但不得替代这四段。
- `## Alternatives considered` 必须列至少一条，且每条写清**为什么落选**——没记录打败过什么的决策会被重新争论。备选不是编出来的：想不起来当时考虑过什么，就写清「当时没考虑别的方案」。
- 事实跟随代码：note 里提到的路径、字段名、默认值在后续改动里变了，同一批改动里改它。**决策本身**不变就不另写一条。
- 缺口的家是 [TECH_DEBT.md](../TECH_DEBT.md)，不是 note：note 记决策，台账记"还没做到的事"。

一条可对照的实例：[删除审计线](implemented/2026-09-29-delete-audit-line.md)。
