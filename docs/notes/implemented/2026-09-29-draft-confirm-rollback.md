# Note: 草稿区、确认落库与可回滚的写入面

Status: implemented

## Problem

P2 要把"素材 → 卡片"接上，而这一步第一次让插件**写**用户的库。三件事必须同时成立：未确认的草稿不能让模型检索到（否则半成品会当结论用）；落库必须是用户看过差异后的动作（不是模型自己决定）；任何一次落库都要能原样退回去（用户的知识库不能因为插件出错而损坏）。

## Decision

1. **写入面分层**：草稿只落 `.dsh-ip-wiki/`（`drafts/` 待确认、`archive/` 已决、`backups/` 回滚点、`log.md` 审计）；**`cards/` 只在用户确认时被写**，且是"先备份、再原子写（临时文件 + rename）、再记日志"三步。
2. **草稿不可见**：读取与检索（`listCards` / `ip_wiki_search` / `ip_wiki_get`）只扫 `cards/`，草稿区不在任何读取路径上——因此"未确认草稿对模型不可见"是结构性的，不是靠约定。
3. **幂等键**：`draftId = sha256(库根 | 目标路径 | 内容)` 前 16 位。同素材同内容重复提交得到同一个草稿 id，不会堆出多份。
4. **回滚**：确认时若目标卡已存在，先把原文件复制到 `backups/<draftId>/`；`revert` 把备份写回（或删除新建的文件），再记一条日志。回滚后库内容与确认前逐字节一致（有测试与真库证据钉住）。
5. **来源分级是可执行的规则，不是口号**：草稿记录素材来源类别（`public` / `client-material`）与生成者（`human` / `model`）。`sourcePolicy.clientMaterial` 默认为 `local-only`：当素材是客户材料且策略为 local-only 时，**声明由模型生成的草稿会被拒绝**（响亮失败），因为插件无法阻止模型已经看到素材，但可以拒绝把"云端模型生成"这件事写进库。
6. **审计只追加**：`log.md` 每次动作追加一行（时间、动作、草稿 id、目标路径、来源、策略、哈希），不重写。

## Alternatives considered

- **草稿直接写 `cards/` 并标记 `status: draft`** — 落选：那样草稿立刻进入检索面，模型会把半成品当结论引用；分层目录让"不可见"成为结构性事实。
- **确认时直接覆盖目标文件** — 落选：没有备份就没有回滚；覆盖前复制一份到 `backups/<draftId>/` 的代价可以忽略。
- **把"客户端材料不得外送"做成插件内的强制拦截** — 落选：模型调用工具时已经看过素材，插件拦不住已发生的阅读；能强制的是"不把云端生成这件事写进库"，因此把它做成可执行的拒绝规则，其余靠指引段写清。
- **用 git 做回滚** — 落选：库根明确不入 git（用户决定），插件必须自带备份与回滚。

## Consequences

- 换来：草稿结构性不可见；落库必经确认；每次落库可逐字节回滚；审计可追溯。
- 付出：库根下多一个 `.dsh-ip-wiki/` 目录（派生品，可整体删除）；备份会随确认次数增长（当前每次确认只备份被替换的那一个文件）。
