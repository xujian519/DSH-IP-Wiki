# Note: 池子取 40 张，答案列表里近似重复的卡排到末尾

Status: implemented

## Problem

上一轮（`2026-09-29-recall-pool-stage-share.md`）给每个召回阶段留了保底席位后，真库（1,137 张）的 `p1-eval` 从 12/20、15/20 回到 13/20、15/20，但仍有 5 题金标进不了前三，其中 3 题前十都进不去。当时的判断是"**精排更偏爱同族卡**"。这一轮把它量清楚了，结论是**那个判断不成立**。

做法：写了一个诊断脚本，用真的语料、真的本地端点、真的精排跑完整管线，并用一个 `fetch` 替身**记录精排实际收到的文档和每份文档的分数**（走线证据，不是复现），再用本地重建的两个召回阶段给池子里每张卡标注它在关键词级、向量级的全库名次，并对重建结果做一致性核对（20 份提交文档 20/20 对得上，池子集合与走线一致）。

量到的（20 题逐题）：

1. **金标 19/20 题都进了池子**，向量级名次普遍是第 1–7（8 题第 1）。召回不再是瓶颈。
2. **同族/同主题限席对结果没有任何影响**：源页≤1、主题≤2、主题≤3 三种限席策略下命中@1、命中@3 都是 13/20、15/20，一个不差。逐题看也能解释：前十里的卡**大多来自不同源页**（源页 ×1），把同族卡压下去腾不出位置给金标——金标本来就在第 10–15 位，压掉 2–4 张同主题卡也够不到前三。
3. **RRF（关键词+向量+精排三路排名融合）更差**：三路 10/20、14/20；向量+精排 11/20、15/20。精排单独排序是目前最好的排序信号。
4. **一题（#7）确实是召回丢的**：金标在关键词级第 20、向量级第 19，20 个池位刚好把它挡在外面。池子放到 40 后它进池，精排把它排到**第 2**（模拟与走线池在同一批文档上一致）。命中@3 因此 15/20 → 16/20。
5. **前十里有近似重复的卡**（另一件真问题）：12/20 题的前十里存在余弦 ≥0.97 的卡对，最相似的一对是 1.000，且多是**同一问题被改写的多张卡**（如 #2 前十里有 6 张同题改写、#12 与 #16 各有 3 张）。这类重复与"同族页面"不是一回事，它们来自卡片层自己的重复。
6. **端到端对照：整卡前 4000 字与整卡全文的精排分数与 1200 字完全相同**——端点把输入截断在 1200 字左右，所以"喂更长文本给精排"这条路不通（实测也无改善）。

## Decision

1. **`CANDIDATES` 20 → 40**（`src/host/search.ts`）。池子大小同时决定每阶段的保底席位（`STAGE_SLOTS = CANDIDATES / 2`），所以 40 等于把关键词级、向量级各自的保底从 10 提到 20，边界题的金标因此进得了池。代价是一次更长的精排调用（≤40 份文档，无额外嵌入）。
   上一轮把"只调大 `CANDIDATES`"列为"缓解不是修复"，这条**按实测修正**：真正的指标增益来自保底席位随池子同步变大，而不是池子变大本身能兜住关键词侧的洪流。
2. **近似重复排到末尾**：`DUPLICATE_COSINE = 0.97`，池内候选按最终次序走一遍，与已保留的卡余弦 ≥ 阈值者移到自己那一段的末尾（`suppressNearDuplicates`，纯函数）。用嵌入向量判定，阈值来自实测分离度：**同题改写 0.97–1.00，同一页的不同章节碎片只有 0.87–0.96**（碎片带着自己那节正文，所以不会跟兄弟碎片被判成重复）。
   在最近用与精排成功之后执行；**在用卡与已废弃卡各自做一遍再拼接**，否则移动可能把在用卡排到已废弃卡后面（已废弃卡排在末尾是上一轮的决定）。移动数量通过 `SearchResult.duplicates` 报给面板与工具输出（`近似重复 N`），列表不再严格按分数排列这件事因此是可见的，不是暗改。
3. **测试**：`suppressNearDuplicates` 两条单测（移动、无向量不动）；管线三条（重复卡排到不同卡之后、在用重复卡不越过已废弃卡、精排收到 40 份候选）。
   负控制三条都跑了：`CANDIDATES` 改回 20 → 池子大小那条报 `expected [ …(20) ] to have a length of 40 but got 20`；`DUPLICATE_COSINE = 2`（等于关掉）→ 两条去重测试红；`STAGE_SLOTS = 0` → 原"每阶段保底席位"那条红（它已重写为**读精排请求里的候选池**，不再靠命中条数间接推断，否则会被去重顺带救活、失去控制力）。

## Alternatives considered

- **同主题限席 / 同源页限席**（用户当时指的方向）——实测对指标零影响（见上），且"主题"只能靠源路径目录表达，那对卡片层（117 张同在一个目录）语义是错的。所以不做；如果只是想让列表里少一些同主题卡，可以单独再议，但要说清它不改善召回。
- **整理层（vault-card）整层排在导入层之前**——实测 17/20、18/20，是唯一能让指标过线（14/18）的机制。但它同时**降低**了部分题目的答案质量：#5 的前三从「功能性限定」相关的三张卡变成三张同题改写的"权利要求书撰写要求"卡；#13 的前三变成三张泛泛的"辅助判断因素"卡。而且 P1 的金标全部取自卡片层，这个策略在指标上是**自我印证**的：它主要衡量"层内排序好不好"（层内 17/18，与导入前的 17/19 相当），不能独立证明跨层排序更对。因此**不改**，作为待用户决定的策略交给用户（见设计文档 §24）。
- **RRF 融合三路排名**——更标准，但实测更差（见上），不做。
- **把近似重复的卡在库里合并掉**（走既有合并流程：`supersedes` + 确认）——这才是治本，而且用户可逐份复核；但那是改用户的库内容，得由用户决定。本轮只把量出来的重复组清单交给用户（见设计文档 §24），已在排序层做的去重是可回滚的展示规则，不写库。
- **按标题判重**——只认逐字同题，抓不到改写（#12 的三张标题只差一个"的"），漏得多。

## Consequences

- 换来：边界题的召回（命中@3 15 → 16/20）；答案列表里不再连续出现同一问题的多张改写卡；"列表为什么不是按分数排的"第一次有数字可说（`duplicates`）。
- 付出：精排调用变长（≤40 份）；两个新的排序规则（近似重复、已废弃）叠加，答案列表不再是分数的单调函数——两条规则都只**后移**、都报数，才没变成隐性错排。
- 教训：**"某个策略更好"要按逐题的答案质量核对，不能只看指标**。这一轮里"整理层整层在前"指标最好而列表更糟；"同族限席"直觉最像用户描述的病而实测零影响。**手工转录金标字符串也会造假**——诊断脚本最初手抄 20 题金标，把 #2 抄成 `…与说明-une3vr`（真名是 `…与说-une3vr`），于是凭空多出一题"未命中"；现在金标只有一份，`tests/p1-cases.ts` 同时给验收与诊断用。
