# Note: Wiki 批次导入的映射与取舍

Status: implemented

## Problem

宝宸 vault 的 `Wiki/` 有 1,165 个 md，方案 §3.3 只写了"① 结构化程度高的（审查指南/法条/侵权判定指南）优先迁移；② 判决与复审聚合页先保留 `raw/` 来源，按需抽取案例卡"，没有可执行的判定口径。实际动手时，四个"照名字/照目录猜"的假设全部被数据推翻：

1. **拆分家族里父页是索引壳、碎片才是正文**：`修改-直接毫无疑义确定（上）.md` 只有 456 字节（"拆分自 + 分拆目录"），它的 `-拆分-01-基于公知常识的技术特征改变.md` 有 7,478 字节。按"留整页、弃碎片"处理会毁掉 161 页正文。
2. **法条正文在引用块里**：`专利法-2020-拆分-02-第三章-专利的申请.md` 14,680 字节，第一版量测给它 0 字（把 `>` 行全丢了）。
3. **个人笔记把整段话写在 `###` 标题行里**：只按普通段落量测时，41 张笔记只认出 4 张。
4. **YAML frontmatter 被当成正文**：一批 300 字节的"只有 frontmatter 没有正文"的化学 stub 因此越过了正文门槛。

还有一条与方案描述不符的事实：`复审无效` 与 `专利判决` 下的页**不是原始聚合，而是提炼层**——`复审无效/说明书/说明书-审查标准-计算.md` 的 `溯源` 指向 `Raw/无效复审决定/2015107074621.md`，而 `Raw/无效复审决定/` 有 31,569 个原始决定文件。原始层留在 vault 的 `Raw/` 不进库，Wiki 页是有正文的提炼页，因此按"有正文就收"处理，"全部导入"与方案的分层不冲突。

## Decision

`scripts/import-wiki.ts`（**只生成草稿，从不写卡片**）：

1. **判定按内容量测，不按文件名**：剔除导航/元数据（57 页：`index.md`/`log.md`/`CLAUDE.md`/`All-Concepts*`/`Concept-*`/`_orphan_analysis`/调研报告/健康报告）后，正文 ≥ 200 字的页才收（998 页）；正文量计入普通段落、长引用块（条文原文）、长标题行（个人笔记的写法），剔除元数据块、表格行与链接清单，并先剥掉 leading YAML 块。
2. **正文逐字节相同只留一张**（按内容 sha256 去重，报告被丢弃的每一页）。
3. **标题三级回落**：`# ` 标题 → 若标题是通用小节名（决定要点/裁判规则/核心要点…）或**被多页共用**（五辑案件指导都用系列名作标题）则回落文件名 → 文件名再去掉尾部的 `（N）` 复制标记。
4. **卡型与业务域按子树 + 文件名模式确定性映射**（`statute`/`case`/`rule`/`concept`；`domain_l2` 用表格映射到既有域词表，源里没有的域值如"商标"直接新增）。
5. **`concept` 用 vault 自己的 `wiki-concept-index.json`**（1,165 页命中）。
6. **`related_concepts` 只写解析成功的 id，且链接在整批内解析**：页内 `[[…]]` 按"页路径 → 文件名 → 标题"三级解析成本次导入的卡片 id（歧义不猜），解析不出的 565 条留在 `wiki_links`。**整批一次落库**，因此不存在"链接指向尚未导入的卡"的中间态，`broken-link` 保持 0；若按 200 张分批落，中间态会带大量断链 warning。
7. **时间戳取源文件 mtime**，草稿 id 由"目标路径 + 卡片全文"决定 → 同一份 vault 重跑 id 不变（幂等，不重复排队）。
8. **`status: "draft"`**：落库 ≠ 有人读过。与 130 张迁移卡同一约定，之后用 `ip_wiki_confirm` 排队确认。

## Alternatives considered

- **按文件名/目录规则决定收哪些页** — 落选：上面四个假设全错。
- **把 57 页导航与 109 页壳页也收成卡** — 落选：源自己的 `Wiki/审查指南/index.md` 写「总计 86 张卡片」，而该子树有 87 页有正文，说明源也不把索引壳当卡片。
- **让模型把每页改写成卡片文本** — 落选：这些页已经是提炼层，重写只会引入无法核对的内容；正文原样搬运才能让 `ip_wiki_cite` 逐字核对。
- **分批落库（每批 200 张）** — 落选（作为默认）：链接跨批，分批会在中间态产生数百条 `broken-link` warning。`--batch-size` 仍保留作为降级手段。
- **不写 `related_concepts`** — 落选：真库副本实测 998 页会变成 998 张孤立卡（`orphan-card`），把门禁信号埋掉。
- **把链接补全做成第二遍"更新"批次** — 落选：写面没有"更新既有卡"的草稿种类，第二遍等于把 998 张卡再写一遍。

## Consequences

- 换来：998 页成为可检索、可引用、可回滚的卡片；映射规则确定性、可复跑、幂等。
- 真库副本预演（139 → 1,137 张）：索引无漂移、`broken-link` 0、998 份整批回滚后**树哈希逐字节复原**（53.6 秒）。
- 代价与工作清单：落库后门禁新增 `low-confidence` 219（标题回落/无元数据的页，正是要人工看的清单）、`unclassified` 51、`orphan-card` 83、`duplicate-title` 8（4 组源内同题，正是下一批合并的输入）。
- `normalizeTitle` 从 `lint.ts` 导出，供本脚本按门禁自己的口径预测撞车，避免两处各写一份归一化必然漂移。
