# Note: 正文双链认下 Obsidian 的 `#锚点` 与 `|别名` 两种写法

Status: implemented

## Problem

[README](../../../README.md) 的边界第 3 条写着"`[[双链]]` 只是显示…尚未解析成可跳转的卡片"。本轮核对时这句话**已经是错的**：`IpWikiPage.tsx` 的 `linkResolver` 早就按「卡片 id / 标题 / 文件名 / 页名」建好索引，`markdown.tsx` 的 `inline()` 也早就把解析得出的双链渲染成可点控件、解析不出的保持纯文本，并且有一条测试同时断言两条路（点开正文双链跳到正确的卡、未知链接保持纯文本）。文档停在了一个已经不存在的状态。

真正还缺的是 Obsidian 的另外两种写法。真库 5,513 条正文双链里：

- **550 条是别名式 `[[页名|显示文字]]`**（`[[商标法#第十一条-显著性|商标法第11条 - 显著性]]` 这样的写法在 vault 里到处都是）；
- **16 条带 `#` 锚点**。

旧实现把整个 `页名|显示文字` 当成名字去解析，于是必然解析不出，读者看到的是生标记本身。

## Decision

引用取 `|` 之前、再去掉 `#…` 之后的那一段；显示取 `|` 之后的文字，没有 `|` 时显示原文。空 label（`[[页名|]]`）回落到引用名——一个没有文字的控件比重复一次名字更糟。解析得出就是可点的按钮，解析不出仍是纯文本，这条原则不变。

**真库实测**：5,513 条正文双链里，按这个口径 **4,125 条**能解析到卡；其中 **400 条**是这次才从"生文本"变成"可跳"的。

**锚点不滚动**：只认出"是哪一页"，跳到卡，不滚到小节。

## Alternatives considered

- **只拆 `|`、不拆 `#`** —— 落选：带锚点的 16 条同样解析不出，而多拆一个 `#` 是一行 `replace`。
- **连锚点滚动一起做** —— 落选：目标卡的正文要到取回来之后才知道有哪些标题 id，这是一条新的异步路径（取卡 → 查锚点 → 滚动）；只有 16 条链接用得上，先不做，写进台账。
- **让 `WikilinkAccess.resolve` 自己拆 `|` 与 `#`** —— 落选：`resolve` 的契约是"给一个页名还一个路径"，标记是渲染层的事。拆在 `inline()` 里还有一个好处：解析不出时也能显示干净的 label，而不是把生标记摊给读者。
- **别名式解析不出时显示整串** —— 落选：读者从 `商标法#第十一条-显著性|商标法第11条 - 显著性` 里读不出东西，显示 label 至少可读。
- **顺手把 README 那条边界删掉、不写这一笔** —— 落选：边界是给使用者的诚实清单，这一条不是"没有了"，而是"有两种写法，锚点不滚动"，得照实写。

## Consequences

- 换来：550 条别名式双链不再显示生标记，400 条从"看起来能点却点不动"变成可点；README 边界第 3 条改成事实（含"锚点不滚动"与 4,125/5,513 这两个可重跑的数字）。
- 换来：`tests/markdown.spec.tsx` 多一个 `wikilinks` 分组，覆盖「带锚点带别名」「只有锚点」「解析不出的别名」「空 label」四种写法，以及"没有 resolver 时全部保持纯文本"。
- 付出：无。渲染分支多了一次字符串处理。
- 仍未做：锚点不滚动（见上）；`[[页名#小节]]` 这种没有 label 的写法则把 `页名#小节` 原样显示出来，不改成别的样子——不做没实现的样式。
