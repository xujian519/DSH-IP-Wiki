# Note: 门禁加两条规则：该建哪张卡、哪个域是孤岛（并否掉两条图度量）

Status: implemented

## Problem

1,137 张导入完之后，门禁报 422 条 findings，全部是"哪里不对"，没有一条是"下一步做什么"。两类现成的信号没人用：

- **`wiki_links` 是死字段**。导入脚本把解析不出的链接目标写进卡片的 `wiki_links`（它自己的报告写着"565 条解析不出的目标留在 `wiki_links`，不参与门禁"），而插件代码从不读它——只有 `scripts/import-wiki.ts` 写。它其实是一份现成的"被反复提到、却没有自己的卡"的清单。
- **门禁看不见结构**。`orphan-card` 只看单张卡有没有互链，不看**域**：一个域整体与库的其余部分断开，规则完全看不见。

## Decision

两条 `suggestion` 规则，都是纯计算、无 LLM，与面板「质量门禁」、`ip_wiki_lint`、`GET /lint` 同一套实现。

1. **`wanted-card`**。把 `wiki_links` 里被 **10 张以上**卡提到、且至今没有对应卡的目标列为一条 finding，按被提到次数降序（报告的排序是稳定的，所以列表本身就是优先级）。"至今没有对应卡"是重新解析出来的，不是当年导入的结论：目标按归一化标题与卡片 id 比一遍，已经被某张卡回答的目标自动离开报告——否则这条规则永远不消。
2. **`island-domain`**。某个 `domain_l2` 有 **≥5 张在用卡**、且**双向零互链**（没有任何在用卡引用域外、也没有域外卡引用它）时报一条。库里只有一个域时不报：那时"与其它域没有互链"是空真命题。

**真库实测（1,155 张）**：`wanted-card` **34 条**、`island-domain` **1 条**（`商标`，24 张卡双向零互链），总 findings 422 → 453。

**被实测否掉的两条图度量**（同一轮量出来的数字，留档以免重来）：

- **`bridge-card`**：邻居跨 ≥3 个业务域的卡有 **211 张**（≥4 域 80 张、≥5 域 28 张、≥7 域 9 张）。这不是缺陷而是优点——"这张卡通着七个域"没有任何可修复的动作，而且门禁的 `failOn` 语义把它当成待清项，211 条不可消解的"你很好"会把报告淹掉。
- **`dangling-domain`**：跨域有向对里只有单向的有 **19 对**，头几名清一色 `法律法规→X`（`法律法规→程序问题` 22 条边、`法律法规→专利审查` 19 条）。法条被引用而自身不反引是**结构使然**（法条指向的是"法律条文"，不是"引用它的程序卡"），不是缺陷。

## Alternatives considered

- **把 `wiki_links` 的目标直接回填成 `related_concepts`** —— 落选：那 725 个未解析目标里绝大多数没有对应的卡，写进 `related_concepts` 会立刻把断链从 0 变成几百条，等于用一条规则拆掉另一条规则；它们该变成"建卡清单"而不是"引用"。
- **`wanted-card` 不限阈值，全都报** —— 落选：725 个未解析目标里 357 个只被一张卡提过一次，全报就是 725 条噪音，把 422 条已有的 findings 淹掉。阈值 10 让它是 34 条真正值得建卡的。
- **按"提到它的卡的路径"报 finding，而不是库级一条** —— 落选：一个问题会在几百张卡上各报一次，而"要建哪张卡"是库级结论；库级 finding（`path: ''`）是门禁已有的形态（`index-drift` 就是这么报的）。
- **`island-domain` 用"跨域互链占比低于某阈值"** —— 落选：密度与域规模强相关，大域必然低（`权利要求与说明书` 185 张卡只有 0.019）。按占比划线会稳定误报大域；`外观设计` 有 28 条跨域引用、`权属问题` 17 条，它们是"内部聚焦"而不是"被切断"，不该报。
- **域内密度（`sparse-domain`）** —— 落选：同上，规模混淆没解；而且"密度低"对大到 221 张的域根本没法处置。
- **不做 `island-domain`、只做 `wanted-card`** —— 落选：`商标` 这个 24 张卡的孤岛是实测里唯一真正的结构缺陷，且成本只有十几行。

## Consequences

- 换来：`ip_wiki_lint` 与面板现在能回答"下一步建哪些卡"（34 条，按被提到次数排序）和"哪个域进不去"（`商标`）；台账与 README 的规则表跟着改了。
- 换来：门禁负控制 `tests/gates/library-lint-gate.spec.ts` 多两条注入用例（缺卡目标、孤岛域），并且`负控制证明过`：把"已被现有卡回答的目标要排除"这条守卫拿掉后，单测与门禁注入各红一条；把"同域引用不算跨域"拿掉后，同样各红一条。
- 付出：findings 从 422 涨到 453（`failOn=warning` 仍然 `pass`，两条都是 `suggestion`）。`island-domain` 会让"只有一个域之前"的库沉默，但一旦分了第二个域就会开始报——这是有意的。
- 仍未做：findings **不可消解**。`wanted-card` 的目标建了卡就自动离开报告，`island-domain` 补了跨域互链也会离开，但没有"这条我看过了、别再报"的机制；台账里记着。
- 仍未做：图度量只做了这几条，桥接卡与社区检测没有进门禁——真库的 vault 已经跑过 graphify（697 节点 / 1,429 边 / 61 社区），重复造它不划算。
